2. Run it: get the existing tests and the app running in the sandbox BEFORE changing anything.
3. Follow conventions you find (naming, structure, formatting, libraries) - do not introduce a second style.
4. Safety net: if the area you change has no tests, write characterization tests that capture current behaviour.
5. Change in small steps; run the tests after each step.
6. Record what you learned about the project with memory_note so the next session starts faster.
